# Алгоритм работы

Проект реализует прогнозирование дат завершения проекта на основе симуляции Монте-Карло. Основная задача — рассчитать вероятности своевременного завершения работ и визуализировать результаты.

## Алгоритм работы

Алгоритм состоит из следующих этапов:

1. **Ввод исходных данных**:
    - **Начальный объём задач** (*initialWork*, в часах) — общий объём работ в начале симуляции.
    - **Текущий объём задач** (*currentWork*, в часах) — оставшийся объём задач для выполнения.
    - **Средняя скорость выполнения задач (velocity)** (*meanVelocity*, в часах/спринт) — среднее количество работы, которое команда завершает за один спринт.
    - **Отклонение velocity** (*stdVelocity*) — стандартное отклонение средней скорости выполнения задач.
    - **Средний прирост новых задач** (*meanAddvity*, в %) — средний процент прироста новых задач за спринт.
    - **Отклонение прироста задач** (*stdAddvity*, в %) — стандартное отклонение прироста новых задач.
    - **Максимальное количество спринтов** (*maxSprints*) — количество симулируемых спринтов.
    - **Длительность спринта** (*sprintLength*, в днях) — количество календарных дней в одном спринте.
    - **Рабочих часов в день** (*workingHoursPerDay*) — количество рабочих часов в день.
    - **Дата начала** (*startDate*) — дата начала первого спринта.

2. **Расчёт календарного плана спринтов**:
    - Определяются даты начала и окончания каждого спринта на основе заданной длины спринта и выходных дней.
    - Рассчитывается количество доступных рабочих часов для каждого спринта.

3. **Симуляция методом Монте-Карло**:
    - Проводится 10,000 итераций, где моделируется:
        - Выполнение задач с учётом случайной корректировки velocity.
        - Добавление новых задач в конце каждого спринта.
    - Для каждой итерации считается, на каком спринте задачи будут полностью выполнены.

4. **Анализ результатов**:
    - Расчёт вероятностей завершения работы по каждому спринту.
    - Определение ключевых метрик: P10 (оптимистичный срок), медиана (P50), P90 (пессимистичный срок).
    - Подсчёт процента незавершённых задач за максимальное количество спринтов.

5. **Визуализация**:
    - Графики вероятности завершения по спринтам.
    - Кумулятивный график вероятности завершения.
    - Динамика объема задач по итерациям спринта.

## Метрики и их интерпретация

Проект предоставляет следующие ключевые метрики:

### 1. **Наиболее вероятный срок**
- Это спринт, в котором вероятность завершения работы максимальна.
- Помогает определить наиболее вероятную точку завершения проекта.

### 2. **P10 (Оптимистичный срок)**
- Спринт, в котором вероятность завершения достигает или превышает 10%.
- Рискованный, но достижимый, если количество новых задач минимально.

### 3. **P50 (Медианный срок)**
- Спринт, в котором вероятность завершения достигает 50%.
- Отвечает на вопрос: "С какой вероятностью проект завершится к этому сроку?"

### 4. **P90 (Пессимистичный срок)**
- Спринт, в котором вероятность завершения достигает или превышает 90%.
- Используется как ориентир для прогнозирования в худшем случае.

### 5. **Процент незавершённых задач**
- Вероятность того, что проект не будет завершён даже за максимальное количество спринтов.
- Важный индикатор рисков для долгосрочного планирования.

### 6. **Календарный план спринтов**
- Таблица с датами начала и окончания каждого спринта, количеством рабочих часов и вероятностью завершения.

## Интерпретация результатов

1. Используйте **график вероятностей завершения** для визуального определения, на каком спринте вероятность завершения вас устраивает.
2. Обратите внимание на P10, P50 и P90:
    - **P10** даёт оптимистичный прогноз, полезный в условиях плотных сроков.
    - **P50** (медиана) — это средний рабочий прогноз для команды.
    - **P90** подходит для минимизации рисков и согласования с осторожным заказчиком.
3. Изучите **график динамики изменений объёма работы**:
    - Позволяет увидеть, как объём задач должен уменьшаться со временем, включая статистические отклонения (P10, P50, P90).

---

> **Примечание**: Метод Монте-Карло предполагает случайные результаты для каждой симуляции, поэтому результаты могут незначительно отличаться при повторных расчётах.
